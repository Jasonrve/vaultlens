- ESLint config (`app/eslint.config.js`) has two separate rule blocks: `src/client/**` (browser globals, React/React Hooks rules, JSX) vs `src/server/**` + `src/shared/**` (node globals, no React rules). Keep new files' globals usage consistent with whichever block they fall under — don't add browser-only APIs to server/shared code or vice versa.
- Unused vars: `@typescript-eslint/no-unused-vars` is `warn`, with `argsIgnorePattern: '^_'` — prefix intentionally-unused function args with `_`.
- `no-undef` is off for server/shared TS (type-aware linting isn't configured, so it produces false positives on ambient/global types like `NodeJS.*`); rely on `tsc` to catch real undefined-identifier issues there, not eslint.
- Self-check convention: for standalone, tricky, non-trivial logic (crypto/signing, auth token glue, parsers), add a sibling `<name>.selfcheck.ts` with plain `node:assert` checks and a one-line comment giving the `npx tsx` invocation, rather than adding a test framework. See `eksAuth.selfcheck.ts` / `auditErrorAttribution.selfcheck.ts` for the pattern.
- `shared/` is for logic that must produce identical results on client and server (currently Vault auth-action mapping and ACL policy evaluation) — changes there must stay framework-agnostic (no DOM or Node-only APIs).
